# 01 — Research Summary: Visual FoxPro

> Status: **Draft for review**. This document summarizes what Joe Pro has to replicate.
> Items marked **⚠ Judgment call** are undocumented, ambiguous, or known to vary between
> VFP versions. Each one records how we plan to handle it.

Target baseline: **Visual FoxPro 9.0 SP2** (2007), the last release. Mainstream support
ended in 2010 and extended support in January 2015. Where earlier versions (FoxPro 2.x
DOS/Windows, VFP 3–8) behave differently, VFP 9 is the reference and older formats are
import-only.

---

## 1. File formats

Almost every VFP design-time artifact is itself **a DBF table with a memo file**. The IDE
stores forms, reports, menus, class libraries and projects as rows in tables with fixed
column schemas. So one solid DBF/FPT reader unlocks nearly all of the migration layer.

| Extension | Companion | What it is | Structure |
|---|---|---|---|
| `.DBF` | `.FPT`, `.CDX` | Table | Binary header + fixed-width records |
| `.FPT` | – | Memo storage for M/G/W/Q fields | Block-based, big-endian header |
| `.CDX` | – | Compound index (many tags in one file) | B-tree, 512-byte nodes |
| `.IDX` | – | Single index (compact or non-compact) | B-tree |
| `.DBC` | `.DCT`, `.DCX` | Database container | A DBF (table flag 0x04) of object rows |
| `.SCX` | `.SCT` | Form / form set | DBF, one row per object |
| `.VCX` | `.VCT` | Visual class library | Same schema as SCX |
| `.FRX` | `.FRT` | Report | DBF, one row per band/object |
| `.LBX` | `.LBT` | Label | Same schema as FRX |
| `.MNX` | `.MNT` | Menu | DBF; generated to `.MPR` code by GENMENU |
| `.PJX` | `.PJT` | Project | DBF, one row per file in the project |
| `.PRG` | `.FXP` (compiled) | Program source | Plain text (ANSI code page) |
| `.QPR` | – | Query generated by the Query Designer | Plain text SELECT-SQL |
| `.H` | – | `#DEFINE` header file | Plain text |

### 1.1 DBF (table)

Header (little-endian unless noted):

| Offset | Size | Meaning |
|---|---|---|
| 0 | 1 | File type: `0x30` VFP, `0x31` VFP with autoincrement, `0x32` VFP with Varchar/Varbinary, `0x03` FoxBASE+/dBASE III without memo, `0xF5` FoxPro 2.x with memo, `0x83` dBASE III with memo |
| 1–3 | 3 | Last update (YY MM DD) |
| 4–7 | 4 | Record count |
| 8–9 | 2 | Header length (position of first record) |
| 10–11 | 2 | Record length (includes the 1-byte deletion flag) |
| 28 | 1 | Table flags: `0x01` has structural CDX, `0x02` has memo, `0x04` is a DBC |
| 29 | 1 | Code page mark |
| 32… | 32 each | Field subrecords, terminated by `0x0D` |
| after `0x0D` | 263 | **VFP only:** backlink, the relative path of the owning `.DBC` (zeros for free tables) |

Field subrecord: name (11 bytes, null-padded), type (1), displacement in record (4),
length (1), decimals (1), field flags (1: `0x01` system/hidden, `0x02` nullable,
`0x04` binary/NOCPTRANS, `0x0C` autoincrement), next autoinc value (4), autoinc step (1).

Records: 1 deletion-flag byte (`*` = deleted, space = active), then fields at their
displacement. The file ends with `0x1A`.

**Field types**

| Code | Type | On-disk encoding |
|---|---|---|
| C | Character | Fixed width, space padded, in the table's code page |
| V | Varchar | Fixed slot. Actual length is in the last byte when shorter; a `_NullFlags` bit marks "short" |
| N / F | Numeric / Float | ASCII digits, right-aligned, fixed decimals |
| B | Double | 8-byte IEEE |
| I | Integer | 4-byte signed |
| Y | Currency | 8-byte int64 scaled by 10,000 |
| D | Date | 8 ASCII chars `YYYYMMDD`, blank = empty date |
| T | DateTime | 4-byte Julian day + 4-byte milliseconds since midnight |
| L | Logical | `T`/`F`/`Y`/`N`/`?`/space |
| M | Memo | 4-byte block number into `.FPT` (older formats: 10 ASCII digits) |
| G | General | Memo block holding an OLE object |
| W | Blob | Memo block, binary |
| Q | Varbinary | Like Varchar, binary |
| 0 | `_NullFlags` | Hidden system field. Bitmap of NULL values and Varchar "short" flags |

**⚠ Judgment calls**
- *Numeric semantics.* N fields store decimal text, but VFP evaluates expressions in
  double precision and rounds for display according to `SET DECIMALS`. We will compute in
  `double` for N/F/B/I (bit-compatible results) and in `decimal` for Y (Currency). The
  storage layer keeps declared width and decimals so overflow behavior (stored as
  asterisks, or an error, depending on context) can be reproduced.
- *Code pages.* The code page byte can be 0 (unmarked). The importer will offer a
  per-table override and a heuristic detector, and will record the choice in the
  migration report.
- *Deleted-but-unpacked records* are carried over with their deleted flag, so `RECALL`
  still works after migration.

### 1.2 FPT (memo)

A 512-byte header: next free block (4 bytes, **big-endian**) and block size at offset 6
(2 bytes, big-endian; default 64). Each memo block starts with type (4 bytes BE: 0 =
picture, 1 = text, 2 = object) and length (4 bytes BE), then the data. Old dBASE `.DBT`
memos differ and will get a separate reader.

### 1.3 CDX / IDX (indexes)

Each CDX holds a "tag bag", a root index that maps tag names to per-tag B-trees. Each
tag has a 1024-byte header (root pointer, free list, key length, options such as
unique/FOR/compact/compound, ascending/descending, and the key and FOR expression source
text) and 512-byte nodes. Leaf nodes use a compressed layout: record number,
duplicate-byte count and trailing-byte count are bit-packed with masks stored in the node.
Keys are transformed so that byte comparison gives the right order (numbers as
order-preserving transformed doubles, dates as Julian numbers, characters via collation
weights).

The **structural CDX** has the table's name and opens automatically. Index tags can be
Regular, Unique (first-key-wins, a legacy behavior), Candidate, or Primary (DBC tables
only).

**⚠ Judgment call.** Microsoft's documentation of node structure is good enough to read
indexes. The weight tables for non-`MACHINE` collations (`GENERAL`, `SPANISH`, and so on)
are **not published**. **Decision:** we never trust the binary B-tree as a source of
truth. We read each tag's *expression, FOR clause, direction, type and collation* and
**rebuild** the index in Joe Pro, then verify record order against a VFP-exported sample
when an oracle is available. The CDX tree is only used for an optional integrity
cross-check.

### 1.4 DBC (database container)

A DBC is a VFP table (`.DBC/.DCT/.DCX`) with columns `OBJECTID, PARENTID, OBJECTTYPE,
OBJECTNAME, PROPERTY (memo), CODE (memo), RIINFO, USER`. Object types include
Database, Table, Field, Index, Relation, View, Connection. The `CODE` memo of the
Database row holds **all stored procedures** as PRG source. `RIINFO` holds referential
integrity settings (cascade/restrict/ignore for update/delete/insert).

**⚠ Judgment call.** The `PROPERTY` memo is an **undocumented binary encoding** of
properties (long names, captions, validation rules, default values, triggers, view SQL,
update criteria, and more), with numeric property IDs. The community has reverse
engineered it, and VFP's own `GENDBC.PRG` shows the mapping indirectly by calling
`DBGETPROP()`. **Decision:** (a) implement a native decoder for the known property IDs;
(b) when a Windows machine with VFP or the VFP OLE DB provider is available, run a
**GENDBC-style extraction** through `DBGETPROP()` and cross-check it against the decoder;
(c) report any unknown property ID verbatim in the migration report and never drop it.

### 1.5 SCX / VCX (forms and class libraries)

Both are DBFs with the same schema: `PLATFORM, UNIQUEID, TIMESTAMP, CLASS, CLASSLOC,
BASECLASS, OBJNAME, PARENT, PROPERTIES (memo), PROTECTED (memo), METHODS (memo),
OBJCODE (memo), OLE, OLE2, RESERVED1…RESERVED8, USER`.

- Each row is one object. `PARENT` is a dotted containership path, for example
  `frmCustomer.pgfMain.Page1`.
- `PROPERTIES` is **plain text**, `name = value` per line, holding only values that
  differ from the parent class. Good news for conversion.
- `METHODS` is **plain text** source (`PROCEDURE Click … ENDPROC`). Also good news.
- `OBJCODE` is compiled p-code. It is undocumented, and we ignore it.
- `RESERVED` columns hold designer metadata: custom property/method declarations
  (`RESERVED3`), the class icon, member data XML (`_MemberData`, VFP 9), and more.
- `OLE`/`OLE2` hold binary ActiveX persistence.

**⚠ Judgment calls:** `TIMESTAMP` uses a packed date/time integer (reverse engineered;
informational only). ActiveX (`OLEControl`) state is opaque. We carry the ProgID/CLSID
and flag the control for manual review.

### 1.6 FRX / LBX (reports and labels)

A DBF with about 75 columns. The important ones: `OBJTYPE` (1 = report header row,
5 = label, 6 = line, 7 = rectangle/shape, 8 = field expression, 9 = band,
10 = group, 17 = picture/OLE, 18 = report variable, 23 = font resource,
25/26 = data environment/cursor), `OBJCODE` (for bands: 0 title, 1 page header,
2 column header, 3 group header, 4 detail, 5 group footer, 6 column footer, 7 page footer,
8 summary), `EXPR`, `VPOS/HPOS/HEIGHT/WIDTH` (in **1/10,000 inch** units),
font columns, `PICTURE` (format mask), `STRETCH`, `FLOAT`, `SUPEXPR` (Print When),
`TOTALTYPE`/`RESETTOTAL` (calculated fields), and `TAG`/`TAG2`.

VFP 9 added the `ReportListener` object model, multiple detail bands, and
`_MemberData`-style extensions stored in the `STYLE` memo as XML.

**⚠ Judgment calls:** `TAG`/`TAG2` on the header row contain a binary Windows `DEVMODE`
printer structure. We extract paper size and orientation and discard the rest, with a
note. Fonts are mapped by name, and missing fonts get a substitution entry in the report.

### 1.7 MNX (menus)

A DBF with columns `OBJTYPE, OBJCODE, NAME, PROMPT, COMMAND, MESSAGE, PROCTYPE,
PROCEDURE, SETUPTYPE, SETUP, CLEANTYPE, CLEANUP, MARK, KEYNAME, KEYLABEL, SKIPFOR,
LEVELNAME, ITEMNUM, COMMENT, LOCATION, …`. The Menu Designer edits the MNX and
GENMENU turns it into `.MPR` code (`DEFINE PAD`, `DEFINE POPUP`, `ON SELECTION`). The
format is fully readable. Shortcut menus use the same structure.

### 1.8 PJX (projects)

A DBF with one row per file: `NAME, TYPE, EXCLUDE, MAINPROG, HOMEDIR, OUTFILE,
DEBUG, ENCRYPT, COMMENTS, LOCAL, KEY, USER, …`. `TYPE` codes include `H` header row,
`P` program, `K` form, `R` report, `B` label, `V` class library, `M` menu,
`d` database, `D` free table, `Q` query, `L` API library, `x` other file,
`T` text. "Excluded" files ship alongside the EXE instead of inside it.

### 1.9 Prior art (reference only; we will not copy code)

- **FoxBin2Prg** (VFPX) and **SCCText/SCCTextX**: convert SCX/VCX/FRX/MNX/PJX/DBC to
  text for source control. They prove that a text representation round-trips, and they
  are useful as a cross-check oracle during testing.
- **GENDBC.PRG** (shipped with VFP): regenerates a DBC as code.
- **X# (XSharp)**: an xBase compiler for .NET with a FoxPro dialect. Evaluated as a
  possible language backend (see architecture doc).
- **VFP OLE DB provider** (32-bit only): the most faithful way to *write* live DBFs
  with correct locking, triggers and index maintenance. Relevant for two-way sync.

## 2. The language

VFP's language is a dynamically typed, xBase-derived, line-oriented language with
procedural code, embedded SQL and single-inheritance OOP.

### 2.1 Lexical and syntactic quirks we must support
- **Keywords may be abbreviated to four characters** (`REPL` = `REPLACE`,
  `MODI COMM` = `MODIFY COMMAND`). This is widely used in legacy code.
- Statements end at end of line. `;` continues a line.
- Comments: `*` or `NOTE` at the start of a line, `&&` inline.
- String delimiters: `"…"`, `'…'`, `[…]`. This makes `[` ambiguous with array
  subscripts. Context decides: after an identifier it is a subscript.
- Date/DateTime literals: `{^2024-01-31}`, `{^2024-01-31 14:30}`, `{}` (empty).
- Preprocessor: `#DEFINE`, `#INCLUDE`, `#IF/#ELIF/#ENDIF`, `#IFDEF`.
- **Macro substitution** `&var` (text substitution at runtime, even for keywords),
  **name expressions** `(cVar)` in place of names, `EVALUATE()` and `EXECSCRIPT()`.
  These make static analysis incomplete by design.
- Text blocks: `TEXT … ENDTEXT` with `TEXTMERGE` (`<<expr>>`).

### 2.2 Types and values
Character, Varchar, Memo, Numeric, Float, Double, Integer, Currency, Date, DateTime,
Logical, General, Blob, Varbinary, Object, and **.NULL.**. Variables are untyped
(`LOCAL x AS Integer` is documentation only, used for IntelliSense). VFP separates
**"empty"** (`EMPTY()`: blank string, 0, `{}`, .F.) from **NULL**.

**String comparison semantics are critical and subtle:** `=` compares up to the length
of the right operand when `SET EXACT OFF`, `==` is exact. SQL comparisons use
`SET ANSI` instead. Trailing blanks are significant in some contexts and not others.

### 2.3 Scoping and name resolution
- `PUBLIC` (global), `PRIVATE` (**dynamically scoped**, visible to called routines),
  `LOCAL` (lexical). Undeclared assignment creates a PRIVATE variable.
- **Field names shadow memory variables** in expressions when the current work area has
  that field. `m.name` forces the variable. This is a major source of latent bugs and the
  migration analyzer must flag ambiguous references.
- Arrays: 1-based, one or two dimensions, resizable (`DIMENSION`, `ALINES`, `ASORT`,
  `ASCAN`, …). Arrays are passed by reference with `@`.
- Parameters are passed by value to functions and by reference to `DO … WITH` by
  default (`SET UDFPARMS`).

### 2.4 Navigational data commands (work areas)
Up to 32,767 **work areas** per data session, each with an alias, a record pointer, a
controlling index order, a filter and relations.

`USE … [IN n] [AGAIN] [ALIAS] [ORDER] [EXCLUSIVE|SHARED]`, `SELECT n|alias`,
`GO TOP|BOTTOM|n`, `SKIP [n]`, `SEEK`/`SEEK()`/`INDEXSEEK()`, `LOCATE … CONTINUE`,
`SCAN [FOR] [WHILE] … ENDSCAN`, `REPLACE … WITH … [FOR]`, `APPEND BLANK`,
`APPEND FROM`, `INSERT INTO`, `DELETE`/`RECALL`/`PACK`/`ZAP`, `SET FILTER`,
`SET ORDER`, `SET KEY`, `SET RELATION … INTO`, `SET SKIP TO` (one-to-many),
`SCATTER/GATHER [MEMVAR|NAME]`, `CALCULATE`, `SUM`, `COUNT`, `AVERAGE`, `TOTAL`,
`COPY TO`, `SORT`, `INDEX ON … TAG`, plus functions such as `EOF() BOF() RECNO()
RECCOUNT() FOUND() DELETED() ALIAS() USED() DBF() FIELD() AFIELDS()`.

**Rushmore** optimizes `FOR` clauses (in both xBase commands and SQL) when predicates
exactly match an index key expression. Performance of legacy apps depends on it.

### 2.5 Multi-user, buffering, transactions
- `RLOCK()/FLOCK()/UNLOCK`, `SET REPROCESS`, `SET MULTILOCKS`, exclusive vs. shared use.
  Under the hood VFP uses byte-range locks on the DBF at fixed, well-known offsets. This
  matters for sync (§3.4 of the architecture doc).
- **Buffering** via `CURSORSETPROP("Buffering", 1–5)`: none, pessimistic/optimistic ×
  row/table. `TABLEUPDATE()`, `TABLEREVERT()`, `GETFLDSTATE()`, `OLDVAL()`,
  `CURVAL()`, `GETNEXTMODIFIED()`.
- `BEGIN TRANSACTION / END TRANSACTION / ROLLBACK`, nestable to 5 levels, **only for DBC
  tables**. They are not crash-durable: an interrupted commit can leave a partial write.
- DBC features: primary/candidate keys, field and record validation rules with messages,
  default values, Insert/Update/Delete **triggers** (logical expressions, usually calling
  stored procedures), **RI Builder** generated code, persistent relations, local views,
  remote views, connections.

### 2.6 SELECT-SQL dialect
`SELECT [DISTINCT] [TOP n [PERCENT]] … FROM … [INNER|LEFT|RIGHT|FULL] JOIN … ON …
WHERE … GROUP BY … HAVING … UNION [ALL] … ORDER BY … INTO CURSOR x [READWRITE]
[NOFILTER] | INTO TABLE | INTO ARRAY | TO FILE | TO PRINTER`.
VFP 9 added subqueries in more positions, derived tables, `UNION` in subqueries and
`SELECT` from cursors produced by earlier `SELECT`s. Also `INSERT`, `UPDATE`
(including `UPDATE … FROM` in VFP 9), `DELETE`, `CREATE TABLE/CURSOR`, `ALTER TABLE`.
Any VFP function (including user-defined functions) may appear in SQL.

**⚠ Judgment calls**
- `SET ENGINEBEHAVIOR 70 | 80 | 90` changes semantics (strict `GROUP BY`, `DISTINCT`
  over memo, `TOP` with ties). **Decision:** default 90. The setting is honored per
  session, and the migration analyzer records the value found in code or config.
- Result column naming (`Exp_1`, `name_a` / `name_b` for duplicates) and result types
  of expressions (for example, a Character column's width equals the first row's result
  width) are only partly documented. **Decision:** replicate them through oracle tests
  against VFP 9.
- `INTO CURSOR` without `NOFILTER` may return a *filtered view of the base table*
  instead of a real result set. **Decision:** always materialize a real cursor. The
  observable difference (for example, `DBF()` returning the base table) is noted as a
  known deviation.
- SQL pass-through (`SQLCONNECT`, `SQLEXEC`, …), remote views and `CursorAdapter` go
  over ODBC/OLE DB to external servers and must keep working with modern providers.

### 2.7 Object model
- `DEFINE CLASS x AS y [OF lib] … ENDDEFINE`, `ADD OBJECT`, `PROTECTED`, `HIDDEN`,
  `DODEFAULT()`, `NODEFAULT`, `THIS / THISFORM / THISFORMSET / PARENT`,
  `CREATEOBJECT`, `NEWOBJECT`, `ADDOBJECT`, `ADDPROPERTY`, `REMOVEOBJECT`,
  `_ACCESS`/`_ASSIGN` methods, `THIS_ACCESS`, `BINDEVENT/RAISEEVENT`, `COMPOBJ`,
  `AMEMBERS`, `PEMSTATUS`. Single inheritance. Classes live in PRGs or VCX libraries
  (`SET CLASSLIB`, `SET PROCEDURE`).
- **Base classes:** Form, FormSet, Toolbar, CommandButton, CommandGroup, OptionButton,
  OptionGroup, CheckBox, TextBox, EditBox, Spinner, ComboBox, ListBox, Grid, Column,
  Header, Label, Shape, Line, Image, Timer, PageFrame, Page, Container, Control, Custom,
  Separator, Hyperlink, OLEControl, OLEBoundControl, Session, Collection, Empty,
  Exception, DataEnvironment, Cursor, Relation, CursorAdapter, ReportListener,
  ProjectHook, XMLAdapter/XMLTable/XMLField.
- **Event sequence** (form with a data environment): DE `BeforeOpenTables` → DE
  `OpenTables` → Form `Load` → member `Init`s (innermost first) → Form `Init` →
  `Show` → `Activate` → `Refresh` → first control `When` → `GotFocus`. Teardown runs
  `QueryUnload` → `Destroy` (form first, then members) → `Unload` → DE
  `CloseTables`. Data-bound controls follow `When → GotFocus → InteractiveChange →
  Valid → LostFocus`.
- Event loop: `READ EVENTS` / `CLEAR EVENTS`. Modal vs. modeless (`WindowType`).
  `Show(1)`. Private data sessions per form (`DataSession = 2`).
- Error handling: `ON ERROR`, per-object `Error` method, `TRY/CATCH/FINALLY/THROW`
  (VFP 8+), `ERROR()`, `MESSAGE()`, `LINENO()`, `AERROR()`.

**⚠ Judgment call.** The exact event order in edge cases (focus changes during `Valid`,
grid column navigation, `Refresh` cascades, `Activate` on modal return) is only partly
documented. **Decision:** build an **event-trace oracle**. We instrument sample forms in
real VFP 9 with `SET EVENTTRACKING ON`, record traces, and make matching traces a
conformance test.

### 2.8 Size of the surface
VFP 9 has **several hundred commands and several hundred built-in functions**, plus
roughly 50 `SET` commands that change runtime semantics globally or per data session.
Parity will be tracked in a machine-readable **coverage matrix** (command/function →
status, tests, known deviations) instead of by gut feeling.

## 4. Summary of judgment calls

| # | Area | Issue | Decision |
|---|---|---|---|
| J1 | CDX | Collation weights unpublished | Rebuild indexes from expressions, verify order by oracle |
| J2 | DBC | `PROPERTY` memo binary undocumented | Native decoder + optional DBGETPROP extraction + report unknowns |
| J3 | SCX/VCX | `OBJCODE`, `TIMESTAMP` undocumented | Ignore p-code (source is present); timestamp informational |
| J4 | ActiveX | OLE persistence opaque | Carry ProgID/CLSID, host via COM on Windows, flag for review |
| J5 | FRX | `DEVMODE` printer blobs | Extract paper/orientation only; note the rest |
| J6 | Numerics | Text-stored N vs. double arithmetic | double arithmetic, decimal Currency, declared width kept |
| J7 | SQL | ENGINEBEHAVIOR, column naming/typing | Default 90, per-session setting, oracle-tested |
| J8 | SQL | Filtered-cursor shortcut | Always materialize; documented deviation |
| J9 | Events | Edge-case event order | Event-trace oracle from real VFP 9 |
| J10 | Unicode | VFP is ANSI/DBCS; `C(n)` = n bytes | Joe Pro `C(n)` = n characters; byte-dependent code flagged |
| J11 | Transactions | VFP transactions not durable | Joe Pro transactions are ACID. This is a deliberate improvement with the same API |
| J12 | Legal | "One-to-one replica" | Clean-room: behavior replicated from public documentation and black-box testing. No Microsoft code, binaries, icons or UI assets; no use of the FoxPro trademark in product naming |

The oracle-based decisions (J1, J7, J9) need **a Windows VM with a licensed copy of VFP 9
SP2** for differential testing. That is a prerequisite for Phase 0.
